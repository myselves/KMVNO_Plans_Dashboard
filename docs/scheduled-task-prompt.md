# 주간 갱신 예약 작업 프롬프트

Claude Desktop 앱의 예약 작업(Scheduled task)에 넣을 프롬프트다.

## 등록 방법

1. Claude Desktop 앱에서 예약 작업을 새로 만든다
2. 실행 위치를 **로컬(Local)** 로 지정한다
   — 클라우드로 만들면 Claude in Chrome에 접근할 수 없어 수집이 실패한다
3. 주기를 **매주 금요일 13:00** 으로 설정한다
4. 아래 프롬프트를 붙여넣고, `<저장소 경로>` 를 실제 클론 위치로 바꾼다
   (예: `~/work/KMVNO_Plans_Dashboard`)

예약 작업은 매번 새 세션에서 시작하므로 프롬프트가 그 자체로 완결돼야 한다.
아래 내용을 임의로 줄이지 말 것.

## 프롬프트

```text
[MVNO 대시보드 주간 자동 갱신 — 로컬 예약 실행]

작업 폴더: <저장소 경로>

mvno-dashboard-update 스킬을 사용해 이 저장소의
MVNO_요금제_비교_대시보드.html 을 최신 데이터로 갱신하고 커밋·푸시까지
완료하라. 저장소의 CLAUDE.md 규칙을 따른다.

시작 전 확인:
- Claude in Chrome 연결 상태를 /chrome 으로 먼저 확인한다. 연결돼 있지
  않으면 데이터를 갱신하지 말고 기존 파일을 그대로 둔 채 "Claude in Chrome
  미연결로 수집 불가"라고 보고하고 종료한다.
- 작업 전 git pull 로 원격 변경분을 먼저 반영한다.
- 매월 첫 실행 여부는 대시보드 UPDATE_META 의 lastUpdated 로 판단한다.
  이전 달이면 14개사 전수 확인, 같은 달이면 1단계 변동 감지 기반 확인
  (+ 모요 미입점 2사: 토스모바일·에스원 안심모바일).

실행 중 원칙:
- 예약 실행이므로 스킬의 '안정 운영 원칙' 중 무인 실행 규칙을 엄격히
  따른다. 기준 상품 단종·스펙 변경 등 사용자 확인이 필요한 상황이면 임의로
  기준을 바꾸지 말고, 해당 카테고리는 기존 데이터를 유지한 채 나머지만
  갱신한 뒤 보고 메시지에 질문을 남긴다.
- 특정 브랜드 수집이 실패하면(사이트 개편·CAPTCHA·로그인 요구 등) 그
  브랜드는 기존 값을 유지하고 UPDATE_META verifiedAt 에 이전 확인일을
  남긴다. 전체 작업을 중단하지 말고 나머지 브랜드를 끝까지 진행한다.
- 모요 전수 스캔이 실패하면 ⑥·⑦ 페이지는 기존 값으로 유지하고 3단계를
  전수 확인으로 전환한다.

완료 절차 (스킬 6단계 검증 체크리스트 전 항목 통과 후):
1. cp "MVNO_요금제_비교_대시보드.html" index.html 로 배포용 사본을
   동기화한다. *.bak 파일은 커밋하지 않는다.
2. 커밋한다. 제목 "주간 대시보드 갱신 YYYY-MM-DD", 본문에 주요 변동 요약
   (변동이 없으면 "전 브랜드 가격 변동 없음").
3. git push -u origin HEAD 로 기본 브랜치에 푸시한다. 네트워크 오류 시
   2s/4s/8s/16s 백오프로 최대 4회 재시도한다. PR은 만들지 않는다.
   푸시되면 Vercel이 자동 배포하므로 별도 배포 작업은 없다.
4. 마지막 메시지는 스킬 6단계의 표준 보고 포맷으로 작성하고 커밋 해시와
   푸시 결과를 덧붙인다.

전 브랜드 변동이 없어도 기준일 라인·UPDATE_META·CHANGELOG("전 브랜드 가격
변동 없음")·HISTORY 회차 추가는 수행하고 커밋한다.
```

## 실행 실패 시

예약 작업은 컴퓨터가 켜져 있고 Desktop 앱이 실행 중일 때만 발화한다.
한 주를 건너뛰어도 대시보드는 직전 데이터로 유지되므로, 놓친 주가 있으면
같은 프롬프트를 수동으로 한 번 실행하면 따라잡는다.
